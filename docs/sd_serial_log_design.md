# SDカード通信ログ設計

**対象ブランチ:** `feature/sd-serial-log`
**更新日:** 2026-10-25

## 目的と範囲

`Serial Log`設定がONのとき、現在選択されているUSB CDC/VCP、Port A UART、またはMBUS UARTから共通RXリングバッファへ届いた受信バイト列を、microSDカードの`/TAB5-LOG/TERMLOG.TXT`へ追記する。ログはUTF-8、VT100制御列、Sixel DCSを含む**生バイト列**であり、Tab5から接続先への送信、DSR/DA応答、時刻ヘッダ、行区切りの追加は含まない。

初期実装では単一固定ファイルを追記専用で使う。ローテーション、圧縮、検索、ログ閲覧、TXとの混在、RTCによる時刻付加は対象外である。ファイル名とディレクトリはFATFSのLFN有無に依存しない8.3形式である。

| 項目 | 値 |
|---|---|
| SDログディレクトリ | `/TAB5-LOG` |
| SDログファイル | `/TAB5-LOG/TERMLOG.TXT` |
| 既定値 | OFF |
| ログキュー | PSRAM byte ring、256 KiB |
| SD書込み単位 | 最大16 KiB |
| 耐障害同期 | 64 KiBごと、または2秒ごとの早い方で`fflush`→`fsync` |
| 最低空き容量 | 2 MiB（以下で`LOW`停止） |
| NoSD/IO再試行 | 30秒間隔 |

## 実行経路と優先順位

`main.cpp`は既存の共有RXリングから最大4 KiBずつ取り出す。VT100パーサへ渡す直前に`sd_serial_log_enqueue_rx()`へコピーするが、この関数は待機、SDMMC、FATFS、LVGL、ログ出力を行わない。ログ用リングに空きがなければ、そのRXチャンクをログ対象からだけ捨て、端末の解析をそのまま続ける。

別タスク`sd_serial_log`がキューを読み、SDファイルの追記、定期`fflush`/`fsync`、容量確認、障害分類を行う。SD遅延や媒体障害が、USB/UARTの受信コールバック、メインのVT100解析、Sixel復号、キーボード処理を待たせないことが最優先である。

ログ用キューは既存の共有RXリングとは別である。PSRAM確保に失敗したときは内部RAMへ大きな代替キューを作らず`MEM`を表示し、通常の端末機能を保護する。

## SDセッションの排他

`sd_dictionary`はSDMMC/FATFSの唯一のセッション管理者である。再帰FreeRTOS mutexで、次の操作を直列化する。

- SDマウント、空き容量照会、アンマウント
- ロガーのopen/write/flush/sync/close
- Dictionary EditorのExport、Import Merge、Import Replace
- Flashへ保存したユーザー辞書のSDバックアップ

辞書SD操作の開始時は、ロガーが現在のファイルを`fflush`/`fsync`してcloseするまで待つ。その後に辞書操作が排他的にマウント、入出力、アンマウントを行い、必ずロガーを再開する。ログ設定がONなら、ロガーは同じ`TERMLOG.TXT`をappendモードで開き直し、保留中のログキューから追記する。

ロガーと辞書操作の同期を待つ間はSD mutexを保持しない。これにより「辞書UIがmutexを握ってロガーclose待ち、ロガーがmutex待ち」というデッドロックを避ける。

## 状態遷移と障害処理

| 状態 | 契機 | ログ受入 | 次の動作 |
|---|---|---|---|
| `OFF` | 設定OFF | しない | open済みなら同期・close・アンマウントする |
| `NoSD` | mount失敗 | しない | 30秒ごとにmountを再試行 |
| `ON` | mount、空き確認、append open成功 | する | 書込み・定期同期を続行 |
| `LOW` | 空き容量が2 MiB以下 | しない | close・アンマウント。OFF→ONまで停止 |
| `FULL` | `ENOSPC`またはerrnoなしの短い書込み | しない | close・アンマウント。OFF→ONまで停止 |
| `RO` | `EROFS`、`EACCES`、`EPERM` | しない | close・アンマウント。OFF→ONまで停止 |
| `IO` | SDMMC/書込み/flush/sync/close失敗 | しない | close・アンマウントし、30秒ごとに再試行 |
| `MEM` | PSRAMキューまたはタスク生成失敗 | しない | 端末機能だけを継続。再起動後に再試行 |

FatFsの空き容量は開始時、以後1 MiB書込みごと、または10秒ごとの早い方で確認する。これは辞書交換が一時ファイルとバックアップを作る余裕を残すための予防策である。実際の書込み長、`fflush`、`fsync`、`fclose`も個別に確認するため、容量や媒体状態が照会直後に変化しても検出する。

SDにカード検出GPIOはないため、物理抜去を即時に知ることはできない。`disk_status_check_enable`と実I/O失敗により検出し、既存のFILE/VFS/SDカード状態を破棄してから再試行する。カードを自動フォーマットしない。

## `+DROP`付加状態

ログキューが満杯なら、受信処理を止めず、ログの一部だけを捨てる。この事実は`+DROP`としてステータスに残る。これは媒体の状態とは別に保持する。例えばカードなしでキューが飽和しても`NoSD+DROP`であり、`NoSD`の30秒再試行を妨げない。同様に`IO+DROP`はI/O回復を継続する。

`+DROP`はSerial LogをOFF→ONに切り替えるとクリアする。これは前回の欠落を明示的に区切ってから新しいログ収集を始めるためである。

## 実機確認項目

1. FAT32カードでOFF→ONし、`Log:ON`と`TERMLOG.TXT`への追記を確認する。再起動とON/OFF後も同一ファイルへ追加されることを確認する。
2. UTF-8、CSI色制御、Sixel、NULを含まない任意バイナリを送り、保存ファイルが受信順の生バイト列であることを比較する。
3. カード未挿入時の`NoSD`、記録中抜去時の`IO`、挿し直し後の30秒以内の再開を確認する。
4. 残容量2 MiB以下で`LOW`、実容量枯渇で`FULL`、書込み拒否で`RO`になり、端末入力と画面表示が継続することを確認する。
5. ログON中にDictionary EditorのExport、Merge Import、Replace Import、手動学習保存を実行し、辞書とログ双方が破損せず、終了後に追記を再開することを確認する。
6. Sixelを段階的に高速転送し、ログ用キューが飽和した際に`+DROP`だけが出て、共有RXリングのオーバーフローや端末停止を増やさないことを確認する。

## 検証上の制約

このサンドボックスにはESP-IDFと`idf.py`がない。C++の構文検査、IME、辞書転送、端末/Sixelのホスト回帰テストは実行できるが、SDMMCマウント、カード抜去、実際のFatFsエラー、USB/UART連続受信の最終確認はESP-IDF v5.5.4環境でビルドしTab5実機で実施する必要がある。
