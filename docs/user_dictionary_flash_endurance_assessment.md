# TAB5 SKK ユーザー辞書とFlash書込み耐久性の評価

**作成者:** Manus AI
**対象:** `feature/local-japanese-ime`

## 結論

旧実装は、漢字候補を確定するたびにユーザー辞書の全内容を一時ファイルへ再出力し、置換していた。そのため、候補学習の頻度に比例してSPIFFSの書込み・ページ再利用・ガベージコレクションが発生していた。現在は学習しない・保留保存・手動保存を選択でき、候補確定ごとの全量更新を行わない。SPIFFSは静的ウェアレベリングを持つが、書込み回数そのものを無害化するものではないため、保存方式の選択はFlash寿命と遅延の観点で重要である。

`userdict`パーティションは `0x0cb000`、すなわち**831,488 bytes（812 KiB、4 KiB単位で203セクタ）**である。十分な空き領域とSPIFFSのウェアレベリングは局所的な消去集中を緩和するが、書込み回数そのものを無害化するものではない。

## 実装済みの書込み経路

1. 候補をEnterまたは`Ctrl+J`で確定する。
2. 学習しない設定では候補順位を変更しない。保留保存と手動保存では、`learn_current_candidate()`がRAM上の保留キューを更新する。
3. 同じ読みの候補を再選択した場合はキューを重複させず、すでにFlash上の先頭候補なら保留も作らない。
4. 保留保存は、60秒の無操作または16件の保留で全量更新を実行する。手動保存は`Ctrl+W`またはSave Learningだけが全量更新を実行する。
5. 手動登録・削除・インポートは明示保存として扱い、Flash保存後にmicroSDへバックアップする。Export SDはFlashを更新しない。

## ESP-IDF上の前提

ESP-IDFのSPIFFSはNOR Flash向けで、静的ウェアレベリングを統合する。一方で、空き容量が少なくなるとガベージコレクションが複数回走り、書込みが遅延・失敗し得る。SPIFFSの電源断耐性は部分的であり、書込み中の電源断では破損する可能性があるが、`esp_spiffs_check()`による復旧を試みられる。

ESP-IDFの一般的なファイルシステム指針は、SPI Flashへの書込み・消去回数を慎重に扱い、余裕あるパーティションを確保するよう勧めている。Flashのセクタ当たりの耐久回数は搭載Flashの型番・データシートに依存するため、本プロジェクトでは一律の寿命年数を保証しない。

## 保存方式の比較

| 方式 | Flash書込み頻度 | 電源断時の学習損失 | 実装複雑度 | 推奨度 |
|:---|:---|:---|:---:|:---:|
| 現行：確定ごと全量書換え | 高い。候補確定ごと | 低いが書込み途中の破損リスクあり | 低 | 不採用 |
| RAM保留＋デバウンス全量保存 | 低い。一定時間・件数ごと | 未保存の学習だけ失う | 中 | **推奨** |
| 追記ログ＋定期コンパクション | 中程度。小さな追記中心 | 追記単位で比較的限定的 | 高 | 将来候補 |
| 学習を完全手動保存 | 最低 | 保存前の学習が失われる | 低 | 設定上の選択肢として有用 |

## 実装結果

1. **既に先頭候補である場合はFlash書込みを行わない。**
2. 保留保存はRAMへ学習差分を保持し、最後の学習から60秒間入力がないとき、または16件の異なる学習変更が溜まったときにまとめて永続化する。
3. 手動保存はDictionary Editorの`Learning pending: N`表示、**Ctrl+W**、またはSave Learningボタンにより保留分を明示保存する。学習しない設定は候補順位を学習しない。
4. 保存中は既存辞書を直接破壊せず、同一ファイルシステム内の一時ファイルを用いて置換する。
5. 手動保存・登録・削除・インポート後はmicroSDへ完全辞書をバックアップする。SDバックアップが失敗してもFlash保存は取り消さず、次回の手動保存またはExport SDで再試行する。

この方式なら、通常の連続入力で多くの候補を確定してもFlash更新は集約される。電源断時に失うのは、最後の保存以降の候補優先順だけであり、システム辞書・補助辞書・既に保存済みのユーザー辞書を失わない設計にできる。
