# 現在の未実装案件

**対象ブランチ:** `feature/local-japanese-ime`  
**基準コミット:** `b08d6be`  
**作成日:** 2026-09-23

## 概要

USB CDC/VCP Host、Port A UART、MBUS UART2、VT100の基本表示、UTF-8/CJK表示、ローカルEcho Back、ローカルSKK、ユーザー辞書、SDカード辞書交換、学習保存モード、および設定画面は実装済みです。現在の未実装案件は、主にSKKの入力効率を上げる拡張と、端末互換性・実機検証の残作業です。

本書の優先度は、既存操作を壊さずに導入できるか、Tab5をシリアル端末として使う頻度が高いか、実装と検証の規模が適切かを基準にしています。

## 次に検討するSKK機能

| 優先度 | 案件 | 現状と未実装の範囲 | 実装前に決める事項 |
|:---:|---|---|---|
| P1 | `/`略語入力 | `/`から英単語・コマンド名・URL断片などを入力し、辞書候補またはそのままの文字列を確定するSKKの略語入力は未実装です。現在のJapaneseモードでは、`/`は略語用の状態へ遷移しません。 | `/`を押した直後の表示、Space時の候補検索、Enter時の直接確定、Esc時の取消、接続先へ送る文字列の規則を定義します。 |
| P1 | temporary ASCIIと`l`小書きかな別名の整理 | 空のかな入力状態で`l`はtemporary ASCII入力を開始します。一方、ローマ字表には`la`、`li`、`ltu`、`lya`など、小書きかな用の`l`別名も残っています。そのため現仕様では`l`別名を実用的に入力できません。 | `x`系のみを小書きかなの標準入力として残して`l`別名を廃止するか、ASCII開始キーまたは遷移条件を変更するかを決めます。端末用途では前者が単純です。 |
| P2 | 数値変換 | 漢数字、全角数字、日付などの数値候補を作る変換は未実装です。数字を含む読みを、通常候補とどう共存させるかも未定義です。 | 対象を漢数字・全角数字・年月日候補のどこまでにするか、候補表示順、桁区切りと負数の扱いを定義します。 |
| P2 | 見出し語補完 | Tabによるユーザー辞書の見出し語補完、複数一致時の候補循環は未実装です。現在のTabは、未確定IME入力を取り消してから接続先へ送ります。 | 補完対象をユーザー辞書だけにするか、補助・システム辞書も含めるかを決めます。候補一覧の表示方法と、Tab／Shift+Tab／Escの操作規則も必要です。 |
| P3 | 単漢字変換・区点入力・半角カナ | DDSKK系で利用できる拡張入力は未実装です。現在の端末用途では利用頻度が限定的です。 | 実際の利用要望がある機能だけを選び、個別に入力規則と候補UIを設計します。 |

## 端末・設定UIの残作業

| 優先度 | 案件 | 内容 |
|:---:|---|---|
| P2 | LVGL標準ドロップダウン障害の根本調査 | 現在は固定候補パネルで安定化しています。標準`lv_dropdown`を戻す必要はありませんが、Tab5の回転・直接描画構成で発生した白点滅の根本原因は未特定です。実機ログ、LVGLの無効化領域、表示完了コールバックを追加して切り分ける場合の調査案件です。 |
| P2 | VT100文字集合切替 | UTF-8と日本語表示は実装済みですが、VT100の文字集合指定シーケンスを用いた文字集合切替は未実装です。英語中心の一般的なxterm互換用途では優先度は低いものの、厳密なVT100互換性を上げる余地があります。 |
| 継続 | ESP-IDF実機ビルド・回帰確認 | この開発環境にはESP-IDFがないため、最新コミットの`idf.py build`、flash、設定画面、学習保存、SDバックアップの組合せはTab5実機で継続確認が必要です。これは機能未実装ではなく検証の残作業です。 |

## 現時点で実装対象にしない事項

連文節変換、外部辞書サーバ、Lisp評価、複雑な文脈学習は、TAB5がスタンドアロンのシリアル端末であることに対して規模が大きく、現時点では実装対象にしません。同様に、辞書全件の一覧表示や常時同期は、SDカードによるエクスポート／マージ・置換インポートが実装済みのため、具体的な利用要望が出るまで保留とします。

接頭辞・接尾辞の変換も未実装ですが、上記P1・P2機能より利用頻度と優先度が低いため、独立した候補として保留します。

## 推奨する次の実装単位

次に着手するなら、**`/`略語入力**と**`l`小書きかな別名の整理**を一つの入力仕様として設計するのが適切です。どちらもJapaneseモード中に英字・コマンド・URLを扱いやすくする課題であり、数値変換や補完より先に基本的な入力の衝突を解消できます。

実装前には、slash略語状態の表示、Space・Enter・Escの振る舞い、`l`別名を廃止するかどうかを、実際のTab5キーボード操作に基づいて合意します。
