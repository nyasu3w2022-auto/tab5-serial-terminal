# TAB5 Sixel Basic / Live Screen 設計

**対象ブランチ:** `feature/sixel-basic`
**対象機種:** M5Stack Tab5（ESP32-P4、1280×720 landscape）

## 目的

TAB5 Serial Terminal が、接続先から送られる **DEC Sixel** グラフィックを、通常の端末画面上に表示できるようにする。対象は、端末利用で実用的な画像表示であり、xterm / VT340 の全グラフィック互換実装ではない。

Sixel は PNG/JPEG を直接送る方式ではない。接続先側で `img2sixel`、Sixel 対応 `gnuplot` などが、DCS（Device Control String）形式へ変換した出力を TAB5 へ送る。

## 実装方針

### 固定・ストリーミング方式

受信した Sixel データを全量バッファへためない。`main/sixel_graphics.cpp` が、受信バイトを1バイトずつ固定サイズのステージング面へデコードする。

- 表示面: 1280×700 logical px（下部20pxのステータスバーを除く）
- 表示ピクセル: RGB565
- 透明領域: 1 bit opacity mask
- ステージング: 8-bit palette index + 1 bit mask
- PSRAM使用量: 約 **2.8 MiB**
- DCS本文の最大長: **1 MiB**
- パレット: 最大256色
- 画像幅・高さ: 各1280 px / 700 px以下
- repeat count: 最大1280

幅・高さ・repeat count・パラメータ桁数・DCS本文長のすべてに上限を置く。入力に従ってメモリを追加確保しないため、壊れた入力や巨大画像要求でPSRAMを枯渇させない。

DCSが正常なST（`ESC \\` または8-bit `0x9c`）で終わるまで、ステージング画像はライブ画面へ反映しない。デコード失敗または上限超過時は、そのDCSだけを破棄し、次のSTまで同期を回復する。既に表示済みの画像は残す。

### 文字と画像の合成

既存の端末画面は、1行ごとのRGB565 Canvasを差分更新する。LVGLの別画像オブジェクトやポップアップを追加せず、各行Canvasの背景を再構築する際にSixelピクセルを合成する。

- 画像ピクセルがある位置は、その色をセル背景へ合成する。
- 既存の文字は画像より前面に描画する。
- **新しく出力される文字、画面消去、行消去**は該当セルの画像ピクセルを消し、文字背景を優先する。
- 文字挿入・削除のように横方向へ文字を動かす編集操作では、誤った位置に画像を残さないよう対象行の画像を消去する。
- `RIS`、`CSI 2 J`、フォントサイズ切替、DECALN、端末スクロールでは画像を消去する。

この方式により、画像を出したあとにプロンプトや入力文字が現れても、画像の一部が文字に残留することはない。一方、Sixelを既存文字の上へ描いた場合でも既存文字は前面に残る。一般的な `img2sixel` のように空行から画像を出す用途を主対象とする。

## 対応する制御

| 種別 | 対応内容 |
|---|---|
| 7-bit DCS | `ESC P ... q` から `ESC \\` まで |
| 8-bit DCS/ST | `0x90 ... q` から `0x9c` まで |
| Sixel data | 6-pixel縦ビットマップ `?`〜`~` |
| カラー選択 | `#Pc` |
| RGB定義 | `#Pc;2;R;G;B`（0〜100%） |
| HLS定義 | `#Pc;1;H;L;S`（DEC Sixel HLS） |
| 繰り返し | `!Pn` |
| Raster attributes | `"Pan;Pad;Ph;Pv`（表示面以内のみ） |
| 水平復帰 / 次バンド | `$` / `-` |
| 背景モード | DCS P2=1 は透明、それ以外は画像矩形を消去してから描画 |
| デバイス属性 | PSRAM面の確保成功時、Primary DAへSixel capability `4`を含めて `CSI ? 1 ; 4 c` を返す |

未対応のDCSは画面へ文字として漏らさず、STまで破棄する。

## カーソルとDECSDM

DEC Sixel scrolling mode（`CSI ? 80 h/l`）を扱う。

| モード | TAB5の動作 |
|---|---|
| `CSI ? 80 h` | 初期値。現在のテキストカーソルを画像左上とし、終端時に画像下の最初のテキスト行へカーソルを進める。画像が下端へ収まらない場合は、必要な行だけ端末を上へスクロールする。 |
| `CSI ? 80 l` | 画像は現在のカーソル位置から表示領域でクリップする。カーソルを移動せず、端末をスクロールしない。 |

Sixel imageは常に logical pixel 座標で表示し、画像自体の自動拡大・縮小は行わない。送信側で画像サイズを調整する。

## バックスクロールとの関係

文字だけの512行PSRAMバックスクロールを維持する。一方、画像付きの完全な履歴は初期実装の対象外である。

- 画像表示中に画面がVT100としてスクロールすると、ライブ画像を全消去する。
- 過去ログのタッチ表示では画像を再表示しない。
- 画像そのものは履歴、SD、Flashへ保存しない。
- タップ/Escでライブ画面へ戻る既存操作は変更しない。

この制限により、過去ログ中で画像が誤った文字行へ貼り付く、または画像履歴がPSRAMを過度に消費する問題を避ける。

## 意図的な非対応範囲

- 画像を含むスクロールバック、alternate screen、コピー、永続保存
- PNG/JPEG/kitty graphics protocol/iTerm2 inline image/ReGIS
- `XTSMGRAPHICS` 問い合わせへの詳細応答
- 任意サイズの画像メモリ確保、拡大縮小、アニメーション
- Sixel macro、color registerのDCS間永続化
- 完全な xterm / VT340 の画像重ね順・消去意味論

## ホスト検証

`tests/sixel_basic_test.cpp` は、ASan/UBSanを付けたホストビルドで以下を検証する。

1. 7-bitと8-bit DCS/ST
2. RGBパレット、透明背景、opaque背景、repeat
3. 通常文字出力によるセル単位の画像消去
4. 不正repeatの中断とST後のパーサ同期回復
5. 既存画像を壊さない異常DCS破棄
6. `CSI 2 J`、`CSI 3 J`、VT100スクロールとの画像状態
7. Sixel capability付きPrimary DA

このSandboxにはESP-IDFがないため、ESP-IDF v5.5.4 の実機ビルド・PSRAM残量・MIPI-DSI描画・USB/UARTの連続受信はTab5実機で確認する必要がある。
