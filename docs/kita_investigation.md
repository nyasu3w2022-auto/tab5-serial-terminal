# 「来た」変換の調査結果

**対象:** `feature/local-japanese-ime` の同梱 `SKK-JISYO.S.txt` と現行IMEコア

## 訂正：一般的なSKKでの正しい入力

**一般的なSKKで「来た」を入力する正しいキー列は `KiTa`** である。語頭の`K`で見出し語「き」を開始し、`T`で送り仮名「た」の開始を指定する。標準の`SKK-JISYO.L`には `きt /来/切/着/.../` が登録されているため、候補「来」を選択すれば「来た」を確定できる。

先行版の本メモで`KuTa`とした説明は誤りだった。`くr /来/.../`は「来る」に対応するキーであり、過去形「来た」の読み「きた」には使用しない。

ただし現行TAB5実装では、同梱の小辞書に`きt`がないため、正しい`KiTa`を入力しても「来た」にならない。これは候補数上限ではなく、辞書資産の不足と探索方式の両方による。

| 項目 | 標準SKK | 現行TAB5同梱辞書 |
|:---|:---|:---|
| 「来た」の正しい入力 | `KiTa` | 同じ |
| 必要な辞書キー | `きt /来/.../` | **未収録** |
| `KiTa`後の現在のフォールバック | — | `き`。候補は気、記、期、機…であり「来」は候補上限以前に存在しない。 |
| 「来る」のキー | `くr /来/.../` | `くr /来/繰/暮/食/` |
| 結論 | `きt`で直接候補化 | 標準辞書の`きt`を同梱するか、`くr`から不規則活用を推定する仕組みが必要。 |

## 実機相当のIMEコア再現

同梱辞書での再現結果は次のとおりであった。

| 入力 | オーバーレイ | Space後の候補 |
|:---|:---|:---|
| `KiTa` | `き / た` | 気、記、期、機…（同梱辞書に`きt`がないため「来」はない） |
| `KuTa` | `く / た` | 喰、朽（「来た」の入力ではない） |
| `KuRu` | `く / る` | 来、繰、暮、食 |

`KuRu`では「来る」を変換できるが、後から「た」へ活用させることはできない。現行TAB5辞書に`きt`がないため、正しいSKK入力である`KiTa`を使っても「来た」を直接入力する実用的な手順はない。

## 推奨修正

まず、標準辞書の`きt /来/.../`を同梱辞書へ反映することが、標準SKKとの互換性を保つ最小の修正である。これにより`KiTa`が直接「来た」を候補化できる。

加えて、既に促音開始の送り仮名で実装した「送りありキー群の探索」を、**送り仮名の先頭が任意のかなである場合**へ一般化すれば、標準S辞書にない活用・語形への補助として利用できる。ただし、これは標準SKKの正しい`きt`登録を置き換えるものではない。
